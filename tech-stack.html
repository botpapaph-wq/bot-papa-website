Under the hood: BOT PAPA tech stack

This page is for people who actually enjoy reading about carriers, call flows and databases. BOT PAPA runs on a small, opinionated stack instead of “every tool under the sun”.

Telephony & call routing

Telnyx (international) Telnyx EU Placetel (EU) Webex softphone

Two backends, no chaos

For cloud telephony and AI phone reception we work with two main backends: Telnyx internationally, and Telnyx plus Placetel inside the EU. Webex is used as a softphone on top of Placetel, and can be integrated with Telnyx where needed.

The goal is boring reliability, not a zoo of random SIP providers. Calls are routed through a small number of well-understood carriers so we can actually debug things when something goes sideways.

AI layer & orchestration

Claude Perplexity comet Custom call orchestration

Conversation brains, not gimmicks

The actual “thinking” for phone bots runs on production-grade LLMs (Claude and others) with a narrow, task-focused prompt layer. Perplexity and comet are used on the research and tooling side, not as black-box magic in your call flow.

Orchestration is kept simple: clear state machines for call flows, explicit hand‑offs to humans and no hidden “let’s see what the model does” in critical branches.

Application stack & data

Cloudflare Supabase GitHub VS Code (Community) Z.com Titan Mail

Hosting, database and code

Public web properties sit behind Cloudflare, with static assets and simple workers where they make sense. Supabase is used for structured data (contacts, configurations) with row-level security turned on by default.

Source code lives on GitHub, day-to-day work happens in Visual Studio Code (Community). Domains and DNS are handled via Z.com, transactional and business email via Titan Mail and Brevo.

Automation & integrations

Make Brevo Slack Discord Telegram WhatsApp Facebook YouTube

Glue between phone, inbox and CRM

Make is used as an automation layer to connect incoming call outcomes and contact form data to email, Brevo and other tools. No-code where it saves time, code where determinism matters.

Slack and Discord are used for internal alerts and monitoring, Telegram and WhatsApp for lightweight notifications and client-side testing. Social channels (Facebook, YouTube) stay strictly at the top of the funnel.

Monitoring, analytics & remote work

Google Analytics Google Tag Manager Clockify TeamViewer (fallback)

Seeing what actually happens

Google Analytics and Google Tag Manager are used for basic traffic and event tracking, with a focus on understanding which calls and forms turn into actual projects – not for building creepy profiles.

Clockify tracks implementation work and support time on projects. TeamViewer is only used as a fallback for remote troubleshooting when there is no other reasonable option.

Data handling & call recordings

✓ No default call recording ✓ Limited retention

Recordings only where they make sense

By default, AI receptionist calls are not recorded just to “have more data”. Recordings are only used for explicit consulting and coaching sessions where both sides agree that review makes sense.

Those recordings are deleted after the project is closed and the agreed warranty period is over. There is no long-term training corpus built out of your customer conversations in the background.

Philosophy

The stack is intentionally small: a few solid carriers, a few solid AI models, one main database and a handful of automation tools. No experimental “vibes-based” infrastructure, no surprise third-party tools that never make it into the proposal.

Who runs this?
